# llm-trading-backtest

로컬 LLM(qwen3, ollama)과 규칙 기반 전략을 **같은 과거 데이터로 정면 대결**시키는 암호화폐 트레이딩 백테스트 프레임워크.

> "LLM이 스스로 판단해서 거래하면 기준치 규칙봇을 이길까?" 를 실제로 검증하는 실험 저장소.

업비트(Upbit) 공개 시세만 사용하는 **페이퍼(모의) 백테스트** — API 키·실거래 없음.

> 📊 **크립토 실험 결과는 [RESULTS.md](RESULTS.md)** (LLM 프롬프트 3라운드 / 평균회귀 / v4 국면적응 / OOS 검증 / HTF 비교 / 규칙 vs LLM 국면판단 / 하이브리드).
> 📈 **국내주식(급등주+DART공시) 실험은 [RESULTS_KR.md](RESULTS_KR.md)** — 순수 급등추격은 엣지 없음(슬리피지에 뒤집힘), **공시촉매 필터를 붙이면 엣지 생성**(단 초대박 의존·생존편향 주의). 다음=LLM이 공시 본문 質 판정.

---

## 무엇을 하나

같은 종목 유니버스(KRW 20종), 같은 지표, 같은 종잣돈/수수료(0.05%)/사이징으로 여러 전략을 동시에 돌려 성적을 비교한다.

- **규칙봇 (추세추종)** — 점수(추세·RSI·거래량·MACD·볼린저·ATR) ≥80 매수, 익절 +3% / 손절 −4% / 추세붕괴 청산
- **LLM봇** — qwen3가 지표를 보고 매수/매도/관망을 **스스로 판단** (프롬프트 v1→v2→v3로 진화)
- **평균회귀 전략** — 볼린저 하단 + RSI 과매도 매수, 평균(MA20) 복귀 시 매도

지표 계산은 매 판단 시점까지의 캔들만 사용(look-ahead 방지). LLM은 ollama 구조화 출력(JSON 스키마)으로 결정을 강제한다. GPU가 불안정한 환경을 위해 `--cpu`(순수 CPU 추론) 지원.

## 구조

| 파일 | 역할 |
|---|---|
| `data.py` | 업비트 과거 캔들 수집·캐시 |
| `indicators.py` | 지표 계산(MA/RSI/볼린저/ATR/MACD, 시점별) |
| `rule_engine.py` | 추세추종 규칙봇 |
| `llm_engine.py` | LLM 판단 엔진 (프롬프트·스키마·파싱) |
| `meanrev_backtest.py` | 평균회귀 전략 백테스트 |
| `portfolio.py` | 페이퍼 계좌(수수료·체결·평가) |
| `backtest.py` | 재생 루프 + 스코어보드 |

## 실행

```bash
pip install -r requirements.txt
python backtest.py --days 7                      # 규칙봇 vs LLM (GPU)
python backtest.py --days 7 --cpu --model qwen3:30b   # CPU 추론
python meanrev_backtest.py                       # 평균회귀 vs 추세추종
```

## 실험 결과 (2026-08, 약 3.4일 횡보장 구간)

### LLM 프롬프트 3라운드 — 시계추 실험

| 버전 | 프롬프트 성향 | 매매횟수 | 승률 | 수익률 |
|---|---|---:|---:|---:|
| **v1** | 완전 자율 | **79** 🔥 과매매 | 32.9% | −0.88% |
| **v2** | 과매매 억제 | **0** 🧊 동결 | — | 0.0% |
| **v3** | 균형(규율) | **7** ✅ | **42.9%** | −0.21% |
| 규칙봇 | 기준치 | 8 | 37.5% | **+0.12%** |

- **v1**: "알아서 판단"시키니 작은 신호에 과매매 → 수수료로 손실
- **v2**: "확신 없으면 사지마"를 강하게 넣으니 아예 동결(0매매)
- **v3**: "좋은 셋업엔 진입 + 현금동결도 손해"로 균형 → 승률은 규칙봇보다 높은데도 수익률은 근소 열세
- **결론**: 잘 튜닝한 LLM ≈ 규칙봇, 근데 무추세장에선 **기계적 규율(+3% 익절 꽉 채우기)이 여전히 근소 우위**

### 돌파구 — 국면에 맞는 전략 (평균회귀)

셋 다 진 진짜 이유: **횡보장인데 전부 추세추종(상승에 매수)** → 꼭지에 사서 썰림.
방향을 뒤집어 **과매도에 사고 평균 복귀에 파니**:

| 전략 | 매매 | 승률 | 수익률 |
|---|---:|---:|---:|
| 추세추종 규칙봇 | 8 | 37.5% | +0.12% |
| **평균회귀** | 26 | **73.1%** | **+0.38%** |

→ 횡보장에선 평균회귀가 압도(수익 3배, 승률 73%). **"국면에 맞는 도구"가 핵심.**

⚠️ 단, 평균회귀는 **횡보장에서만** 유효 — 강한 추세장에선 거꾸로 썰린다. 그리고 3.4일 단일 구간이라 표본이 작다(과최적화 주의).

### v4: 국면 적응형 — 다국면에서 압승

**시장 국면(상승/하락/횡보)을 판단해 국면별 전략을 갈아타는** 적응형 봇 (`regime_adaptive.py`):

- **상승장** → 추세추종 롱 (눌림목 매수, +3% 익절)
- **횡보장** → 평균회귀 롱 (볼린저 하단 과매도 매수)
- **하락장** → **숏** (하락에 베팅, 반등 시 손절) — 페이퍼 시뮬(실거래는 선물 거래소 필요, 업비트=현물전용)

국면판단은 MA 이격도(추세 강도)로 게이팅 — 약하거나 출렁이는 구간은 횡보로 취급해 평균회귀 라우팅.

**핵심: 단일 전략은 특정 국면에서만 통한다.** 짧은 횡보 구간에선 평균회귀가 최고였지만, 상승·하락·횡보가 섞인 긴 구간에선 정반대다:

**90일 다국면 구간** (`backtest_long.py`, 시간봉+일봉, 횡보66%/하락24%/상승9%, 국면전환 64회):

| 전략 | 매매 | 승률 | MDD | 수익률 |
|---|---:|---:|---:|---:|
| 추세추종 | 74 | 54.1% | −1.89% | +1.39% |
| 평균회귀 | 87 | 46.0% | −2.97% | **−2.38%** (여기선 짐!) |
| **국면적응 v4** | 191 | 51.3% | **−1.52%** | **+4.36%** ✅ 압승 |

v4가 **수익률 최고(+4.36%)이자 낙폭 최저(−1.52%)** — 하락장 24%를 숏으로 먹고, 횡보엔 평균회귀, 상승엔 추세추종. 국면을 갈아타며 전 구간을 잡는다. 리스크 대비 수익이 압도적.

**out-of-sample 검증** — 안 겹치는 다른 90일(2026-02~04, `--to`로 과거구간 페치)에서도 재현:

| 전략 | In-sample (5~8월) | Out-of-sample (2~4월) |
|---|---:|---:|
| 추세추종 | +1.39% | +1.41% |
| 평균회귀 | −2.38% | +0.42% |
| **국면적응 v4** | **+4.36%** | **+3.63%** |

평균회귀는 기간 따라 −2.38%↔+0.42%로 널뛰지만, **v4는 두 독립 구간 모두 최고(+3.6~4.4%)** → 특정 기간 과최적화가 아니라 재현되는 우위.

### 현물 배포 검증 — 젯슨 라이브봇(HTF) vs v4 (`htf_vs_v4.py`)

젯슨을 v4로 바꾸는 게 실제로 나은지 검증. HTF = 1h Donchian 돌파 + 샹들리에 트레일링 + BTC 국면필터(젯슨 현재 라이브 전략). **업비트는 현물이라 숏 불가** → 젯슨에 넣을 수 있는 건 "현물 v4(하락장→현금)"뿐.

| 전략 | 매매 | MDD | 수익률 |
|---|---:|---:|---:|
| HTF (젯슨 현재) | 20 | −6.09% | **+2.19%** |
| v4 현물(숏 X) | 104 | −2.55% | +0.47% |
| v4 (숏 포함) | 191 | −1.52% | +4.36% |

**v4의 대박(+4.36%)은 전부 하락장 숏에서 나옴.** 숏을 빼면(현물) +0.47%로 폭락 → HTF(+2.19%)에 짐. **결론: 젯슨(현물)은 HTF 유지가 정답.** v4가 이기려면 숏(선물 거래소)이 필수. → 배포는 반드시 같은 백테스트로 비교 후 결정(안 그랬으면 더 나은 HTF를 더 나쁜 현물v4로 갈아끼울 뻔).

### 국면 "판단"을 LLM에게 (`regime_llm.py`)

전략 실행은 v4와 동일하게 두고, 국면 판단만 규칙(즉시) ↔ LLM(qwen3:30b CPU, 350회 ~4시간)으로 교체:

| 국면판단 | 매매 | MDD | 위험대비수익 | 수익률 |
|---|---:|---:|---:|---:|
| 규칙 | 191 | **−1.52%** | **2.87** | +4.36% |
| LLM | 249 | −2.87% | 1.69 | **+4.86%** |

LLM 판단이 규칙과 일치한 비율 **40%** — LLM은 하락을 더 공격적으로 봐서 숏↑ → raw 수익은 살짝 높지만 **낙폭 2배·연산 4시간**. **위험대비수익·비용 다 규칙이 나음 → 실전 국면판단은 규칙으로 충분.**

### 하이브리드 실험 — HTF + 횡보 평균회귀 결합 (`hybrid_backtest.py`)

현물 최선인 HTF는 '돌파'에서만 진입 → 횡보 구간엔 논다. 그 빈칸을 평균회귀로 메우면 더 벌까? (같은 90일 창, 숏 없음)

| 전략 | 매매 | MDD | 수익률 |
|---|---:|---:|---:|
| 평균회귀 | 116 | −2.48% | **+2.14%** |
| v4 현물(숏 X) | 117 | −2.74% | +1.83% |
| HTF | 25 | −3.08% | −1.05% |
| **하이브리드(HTF+평균회귀)** | 101 | −3.01% | **−0.38%** |

**실패.** 하이브리드는 순수 평균회귀보다도 뒤짐 — 돌파가 안 통하는 구간(횡보66/하락24/상승9%)에서 **국면 안 가리고 돌파진입을 항상 시도** → 나쁜 돌파 손실이 평균회귀 이익을 깎음. **교훈: 전략을 그냥 합치는 것보다 v4처럼 "국면으로 게이팅"하는 게 낫다.** "더 많은 전략"이 아니라 "국면에 맞는 선택"이 엣지.
